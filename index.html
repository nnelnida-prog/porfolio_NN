Case Study: Incomplete Data Entry and Validation in Records

1. Problem

Student and sales records were sometimes submitted with important text fields left completely blank or improperly formatted, resulting in inconsistent data entries.

2. Possible Causes

  • Missing input validation attributes in the HTML form elements.
  • Lack of standard formatting and data rules in spreadsheet or tabular record sheets.

3. Diagnostic Procedure

  • Tested form submissions by leaving required fields empty to check how errors are handled.

  • Applied systematic data organization and formatting rules in Microsoft Excel to clean and structure tabular records.

5. Lesson Learned

Early data validation and meticulous data cleaning are essential to prevent dirty data entry and maintain overall data quality.

Cybersecurity Case Study — SQL Injection (SQLi)

1. What is the vulnerability?

SQL Injection (SQLi) is a web security vulnerability that allows an attacker to interfere with the queries that an application makes to its database. It occurs when untrusted user input is directly concatenated into a database query string without proper validation or sanitization.

2. How can it happen?

It happens when developers construct dynamic database SQL queries by directly combining user inputs (such as login fields, search bars, or URL parameters) into the SQL string.

3. What are the risks?

  • Unauthorized Access: Attackers can bypass authentication forms without valid credentials.
  • Data Exposure: Sensitive database records, user accounts, and passwords can be leaked.
  • Data Tampering: Unauthorized modification, deletion, or corruption of critical database data.

4. How can developers prevent it? (Code Comparison)

❌ Vulnerable Code Example (Direct Concatenation):

// Dangerous: Input is joined directly into the query
String query = "SELECT * FROM users WHERE username = '" + userInput + "' AND password = '" + passInput + "'";
// An attacker entering "' OR '1'='1" bypasses the check.

✅ Secure Code Example (Parameterized Query / Prepared Statement):

// Safe: Placeholders (?) separate user data from database logic
String query = "SELECT * FROM users WHERE username = ? AND password = ?";
PreparedStatement stmt = connection.prepareStatement(query);
stmt.setString(1, userInput);
stmt.setString(2, passInput);
ResultSet rs = stmt.executeQuery();

5. What security practices should be implemented?

  • Use Prepared Statements: Always utilize parameterized queries to treat user input as data, not executable code.
  • Input Validation & Sanitization: Enforce strict input types, lengths, and character filtering on client and server sides.
  • Principle of Least Privilege: Restrict database account permissions so the web application only accesses required resources.

My BSIT Journey: From Fundamentals to Data-Driven Solutions

What Did I Know About IT Before Entering BSIT?

Before entering the Bachelor of Science in Information Technology (BSIT) program at Datamex College of Saint Adeline, my understanding of Information Technology was quite limited and general. Like many beginners, I initially viewed IT as simply knowing how to operate computers, troubleshooting basic hardware issues, or navigating popular software applications. I knew that technology powered modern businesses, but I lacked a deep understanding of how data was structured, analyzed, and transformed into actionable insights. I did not fully grasp the processes behind building functional web applications, managing local databases, or designing structured analytical reports. Entering the BSIT program opened my eyes to the vast ecosystem of technology, showing me that IT is not just about using computers, but about solving real-world operational problems through structured logic, data accuracy, and user-centered solutions.

What Were the Most Important Things I Learned?

Throughout my academic journey, the most important lesson I learned is the value of data integrity, structured analysis, and functional problem-solving. As I progressed in my studies, I discovered my core passion in Data Analytics—specifically using tools like Microsoft Excel to transform unstructured, raw data into clear business reports. I learned how essential data cleaning and data validation are before conducting any meaningful analysis. Mastering key Excel functions such as SUMIFS, COUNTIFS, and logical IF statements, alongside building dynamic Pivot Tables and summary charts, taught me how to present metrics effectively to support decision-making. Beyond technical tools, I developed critical soft skills including systematic problem-solving, attention to detail, time management, and effective documentation.

Which Project Taught Me the Most and Why?

The project that taught me the most was developing and deploying our Student Management System. Building this application served as my primary technical milestone because it challenged me to handle both frontend interfaces and backend logic. This project required implementing essential web features, including user authentication, record creation, dynamic search filtering, and local database management. It taught me how system architecture works in practice—from structuring input validation to organizing data records efficiently. Moreover, publishing this project and deploying a personal portfolio website on GitHub Pages gave me firsthand experience with version control using Git, hosting configurations, and maintaining technical documentation.

What Technical Difficulty Challenged Me Most?

The technical difficulty that challenged me the most was ensuring data accuracy, state management, and debugging errors during system integration and web hosting. While developing the Student Management System, configuring local storage handling and resolving deployment settings on GitHub Pages presented significant challenges. Small syntax mistakes or unhandled edge cases in search filtering often broke system functionality. I overcame these obstacles by adopting a step-by-step debugging approach—testing core functions individually, verifying data flow, and continuously referencing documentation. Similarly, when working on complex analytical reports in Excel, dealing with inconsistent raw data taught me the importance of implementing strict Data Validation rules and using text-to-columns cleaning workflows.

Conclusion

As I prepare to complete my BSIT degree, I look back on my journey with immense pride and gratitude. I have grown from a novice curious about technology into an aspiring Data Analytics professional equipped with practical Excel reporting and web application skills. My journey has prepared me to contribute effectively to data-driven teams, and I am excited to apply my skills to real-world business environments.
